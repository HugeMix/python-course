# PythonBasic — курс Python для начинающих

Интерактивный курс Python на русском языке с преподавателем: 16 уроков с тестами, задачи
с автоматической проверкой, редактор кода, шпаргалка, глоссарий и сертификат.
Урок 1 открыт всем бесплатно. Дальше ученик идёт сам: урок оценивается автоматически, и следующий
оплаченный урок открывается, как только освоен предыдущий. Преподаватель отмечает оплату и смотрит результаты.

Меню сайта — 4 пункта: **Главная · Мои уроки · Практика** (задачи и редактор кода) **· Справочник** (шпаргалка и глоссарий).

Сайт: https://hugemix.github.io/python-course/

Это статический сайт: только HTML, CSS и JavaScript, без сервера и без сборки.
Python выполняется прямо в браузере с помощью [Pyodide](https://pyodide.org/).

## Как запустить локально

Страницы «Задачи» и «Редактор кода» запускают Python в отдельном потоке (Web Worker).
Chrome и Edge не разрешают это для файлов, открытых двойным щелчком (`file://`),
поэтому сайт нужно открывать через локальный сервер:

```bash
python3 -m http.server 8000
```

Затем откройте в браузере http://localhost:8000.

Нужен интернет: Pyodide, редактор CodeMirror и подсветка кода загружаются с CDN.

## Как устроено

**Тесты в уроках** лежат в `script.js`, в объекте `quizData`. Ключ — имя файла урока.
Вопрос с вариантами:

```js
{ question: "Текст вопроса", options: ["A", "B", "C"], correct: 1, explanation: "Почему верно B" }
```

`correct` — номер правильного варианта, считая с нуля. Варианты на странице перемешиваются.

Вопрос с вводом кода:

```js
{ question: "Текст вопроса", type: "code", correct: ["вариант 1", "вариант 2"], explanation: "..." }
```

Ответ сравнивается с вариантами целиком и с учётом регистра.
Пробелы вокруг знаков и скобок не важны, кавычки можно писать любые, но парные.
У вопроса может быть поле `code` — фрагмент программы, который показывается над вариантами
(«Что выведет программа?», «Найдите ошибку»). Если вопросов больше 10, ученику показываются
10 случайных. Урок засчитывается при 70% правильных ответов.

Тест показывает по одному вопросу: после ответа видно, верно ли, и пояснение, затем «Следующий вопрос».
В конце — процент верных ответов, кнопки «дальше / ещё раз» и разбор ошибок. Вариантам ответа можно
выбирать клавишами 1–9. Код теста — раздел «Тест урока» в `script.js`, стили — классы `.qz-*` в `style.css`.

**Устройство урока.** Все уроки построены по одному шаблону:
«Зачем это нужно» → объяснение по шагам → примеры → «Попробуйте сами» (2 упражнения) →
«Частые ошибки новичков» → «Главное за урок» → тест → домашнее задание.

- `<pre data-run>` — пример с кнопкой «Запустить»: код можно изменить прямо на странице.
  `data-stdin="..."` — что подставить в `input()` (строки через перенос).
- `.try-it` — упражнение «Попробуйте сами»: заготовка кода в `textarea.try-code`,
  проверки в `<script type="application/json" class="try-cases">` — список `{"in": ввод, "out": ожидаемый вывод}`.
  Вывод сравнивается без учёта регистра, лишних пробелов, буквы «ё» и точки в конце.
- `.mistake` — частая ошибка: «Так нельзя», «Правильно» и точное сообщение Python.
- Список домашних задач (`.hw-tasks`) сам отмечает решённые задачи.

**Задачи** лежат в `tasks_data.js`. У каждой есть `lesson` — номер урока (по нему задачи
группируются на странице задач) и `hw: true`, если задача входит в домашнее задание урока
(кабинет преподавателя добавляет такие задачи к уроку автоматически).

**Контрольные работы** — задачи с полем `exam: 1 | 2 | 3` (и `lesson` — последний урок блока: 6, 11, 16).
Контрольную выдаёт преподаватель в карточке ученика. На «Моих уроках» видно, сколько задач решено;
контрольная зачтена, если решено 4 из 5. На странице задач у контрольных своя группа (`tasks.html#exam=1`).

Задачи бывают двух видов. Задача «ввод → вывод» (`kind: "io"`, уроки 1–6, до функций):
программа читает `input()` и печатает ответ, а `cases` — список `{in, out}`; программа
запускается на каждом наборе, вывод сравнивается построчно без учёта регистра и лишних пробелов,
а подсказки в `input("...")` в вывод не попадают.

Остальные задачи — функции. Код ученика выполняется в чистом пространстве имён,
после него запускается `testCode`. Задача решена, только если тест дошёл до строки
`__task_passed__ = True` (её ставят перед сообщением об успехе).
Чтобы запретить встроенную функцию или потребовать конструкцию, в тестах есть помощники:

```python
assert not __uses_call__("max"), "Нельзя использовать max()"
assert __uses_node__("Try"), "Используйте try-except"
```

**Режим «Урок по созвону».** На каждом уроке есть кнопка «Провести урок по созвону»:
урок открывается на весь экран слайдами (один раздел — один слайд) крупным шрифтом.
Листать — стрелками ← →, пробелом, кнопками внизу или свайпом на телефоне; `F` — во весь экран,
`Esc` — выйти, `A−`/`A+` — размер шрифта. Ссылка вида `lesson3.html#present` сразу открывает урок слайдами. Кнопка «Провести урок по созвону» видна только в браузере преподавателя (где создан PIN кабинета).
Код режима — функции `initPresentationMode` и `openPresentation` в `script.js`.

**Освоение урока и оценки (считаются сами).** Правила — в `pb-share.js` (`lessonResult`, `computeAccess`);
одни и те же у ученика на сайте и в кабинете (по присланному результату).

- Урок **освоен**, когда тест сдан на 70% и больше и решена домашка — вся или без одной задачи.
- Оценка: **«Отлично»** — тест от 90% и вся домашка; **«Хорошо»** — урок освоен. Не освоен — сайт сам пишет,
  что осталось («пересдать тест — сейчас 60%, нужно 70%», «решить ещё 1 задачу из домашки»).
- Преподаватель может засчитать урок вручную (кнопка «Засчитать», например после занятия по созвону).
- **Контрольная** открывается, когда освоен урок 6, 11 или 16, и зачтена при 4 решённых задачах из 5.
  Пока контрольная 1 (2) не сдана, урок 7 (12) не открывается.

**Работа с учениками (без сервера).** Данные передаются ссылками: JSON сжимается и кладётся
в адрес после `#` (эта часть адреса не уходит на сервер).

1. Урок 1 открыт всем (`FREE_LESSONS` в `pb-share.js`). Закрытый урок показывает карточку с причиной:
   «откроется после урока N», «сначала — контрольная», «оплаченные уроки закончились» или «откроет преподаватель».
2. Ученик платит переводом. Преподаватель в `teacher.html` → «Ученики» добавляет ученика и отмечает оплату
   («+1 урок», «+4 урока»…). Оплачено N уроков — открыты уроки до N+1-го, но по очереди: каждый следующий —
   когда освоен предыдущий. Вручную можно открыть любой урок («Открыть») или выдать контрольную.
3. Кабинет собирает ссылку `python-basic.html#a=…`: сколько уроков оплачено (`paid`), уроки и контрольные,
   открытые вручную, отдельные задачи, комментарии по урокам и сообщение. Преподаватель отправляет её в Telegram;
   ученик открывает — доступ сохраняется в `pb_access`. Новая ссылка заменяет старую, старая (более ранняя)
   не откатывает новую. Новую ссылку нужно отправлять только после оплаты, ручного открытия или комментария.
4. Ученик нажимает «Отправить результат»: ссылка `teacher.html#r=…` (тесты в процентах, решённые задачи,
   ошибки в тестах, код решений открытых задач; не длиннее 3500 символов — помещается в одно сообщение Telegram).
5. Преподаватель открывает её — результат сохраняется в журнал (`pb_journal`) у нужного ученика (по `sid`, затем по имени),
   и в карточке появляется «Новый результат»: оценки, «что осталось», ошибки в тесте и код задач. Делать ничего
   не обязательно: «Посмотрел(а)», по желанию — комментарий. Если ученик освоил все оплаченные уроки, у него
   пометка «Нужна оплата».
6. Журнал живёт только в браузере преподавателя, поэтому кабинет напоминает скачать копию,
   если с последней копии прошло больше 7 дней и журнал менялся (копия — в «⚙ Настройки»).

**Разминка.** В начале каждого урока (кроме первого) — 3 вопроса из прошлых уроков: сначала те, где ученик
ошибался в тестах (`quiz_mistakes`), потом случайные — чаще из прошлого урока. Верный ответ убирает вопрос
из ошибок, неверный — добавляет. Код — `initWarmup` в `script.js`.

В браузере преподавателя (где создан PIN) открыты все уроки, задачи и контрольные — чтобы их можно было показывать.

Баллы: тест — до 10 (лучший результат / 10), задача — лёгкая 1, средняя 2, сложная 3.
Прямые ссылки: `lessonN.html#quiz` — сразу тест, `lessonN.html#present` — слайды, `tasks.html#task=<id>` — задача.

Ограничения: журнал и PIN хранятся в браузере преподавателя (нужна резервная копия — вкладка
«Настройки»); PIN защищает от случайного просмотра, а не от взлома; результат создаётся в браузере ученика
и теоретически может быть подделан. Закрытые уроки закрыты «мягко»: текст урока есть в файле страницы,
и человек, который разбирается в сайтах, может его найти. Для настоящих аккаунтов и защиты нужен сервер.

**Прогресс** хранится только в браузере ученика (`localStorage`):

| Ключ | Что хранит |
|---|---|
| `quiz_results` | Пройденные уроки: `{"lesson1.html": true, ...}` |
| `course_completed_at` | Дата окончания курса (для сертификата) |
| `solved_tasks` | Решённые задачи |
| `saved_code_<id>` | Автосохранённый код задачи |
| `try_done`, `try_code_<id>` | Решённые упражнения «Попробуйте сами» и их код |
| `cert_name`, `cert_number` | Имя и номер в сертификате |
| `theme` | Светлая или тёмная тема |
| `quiz_scores` | Результаты тестов в процентах: лучший, последний, число попыток |
| `pb_access` | Доступ из последней ссылки преподавателя: сколько уроков оплачено, ручные открытия, задачи, комментарии, сообщение |
| `quiz_mistakes` | Вопросы тестов, где ученик ошибся и ещё не исправился (для разминки и для преподавателя) |
| `pb_student_name` | Имя ученика для «Отправить результат» |
| `pb_assignment` | Задание старого образца (читается и переводится в `pb_access`) |
| `pb_teacher_pin`, `pb_journal` | PIN-код (в виде хеша) и журнал преподавателя |
| `pb_journal_changed_at`, `pb_journal_backup_at`, `pb_journal_remind_after` | Когда журнал менялся, когда скачана копия и до какого времени не напоминать о копии |
| `present_slide_<урок>`, `present_scale` | Слайд, на котором остановились, и размер шрифта в режиме «Урок по созвону» |

Так как прогресс хранится в браузере, блокировку уроков и сертификат при желании
можно обойти. Для учебного сайта без регистрации это нормально.

## Автоматическая проверка

В папке `checks/` — две проверки, которые GitHub запускает сам при каждом изменении
(настройка — `.github/workflows/check.yml`). Результат виден на GitHub: зелёная галочка — всё в порядке,
красный крестик — что-то сломано (подробности — во вкладке Actions).

**Публикация идёт только после проверки.** В настройках репозитория Settings → Pages → Source выбрано
«GitHub Actions»: при изменении в `main` сначала выполняется проверка, и только если она прошла,
сайт публикуется (шаг «Публикация» в том же `check.yml`). Если проверка нашла ошибку, на сайте остаётся
прежняя рабочая версия. Если проверка сорвалась из-за сбоя самого GitHub, её можно перезапустить
кнопкой «Re-run» во вкладке Actions. Папки `checks/` и `.github/` на сайт не попадают.

- `check-content.cjs` — без браузера, в настоящем Python (Pyodide, как на сайте): каждый пример урока запускается
  без ошибок; «Частые ошибки» дают ровно то сообщение, что написано; правильные ответы «Что выведет программа?»
  совпадают с настоящим выводом; заготовки упражнений и задач не проходят проверку без решения;
  домашка и ссылки ведут на существующие задачи и файлы; в JavaScript нет синтаксических ошибок.
- `check-pages.cjs` — в браузере Chromium: все страницы открываются без ошибок JavaScript, тест каждого урока
  проходится до конца, в меню ровно 4 пункта, Python запускается, задачи показываются, без ссылки открыт только урок 1,
  весь путь работает: оплата → ссылка → урок освоен → следующий открылся сам → разминка → результат с оценкой
  в кабинете → «Нужна оплата» → оплата → следующий урок; на телефоне ничего не вылезает за экран.
  На GitHub проверка берёт уже установленный Google Chrome (`PW_CHANNEL=chrome`), у себя — Chromium от Playwright.

Запустить у себя:

```bash
cd checks && npm install && npx playwright install chromium
node check-content.cjs && node check-pages.cjs
```

Пример, который специально падает с ошибкой, помечается атрибутом `data-expect-error="ValueError"`,
а ввод для `input()` в блоке «Частые ошибки» — атрибутом `data-stdin` у `.mistake`.

## Как добавить урок

1. Скопируйте любой `lessonN.html`, поменяйте номер, заголовки, `canonical` и `og:url`.
2. Добавьте файл в массив `lessonsList` в начале `script.js` и тесты в `quizData`.
3. Добавьте название урока в `LESSON_TITLES` в `pb-share.js` (по нему строятся «Мои уроки» и кабинет)
   и, если нужно, поправьте модули `MODULES` в `python-basic.html`.
4. Добавьте адрес в `sitemap.xml`.
5. Если меняется общее число уроков, поправьте `LESSONS_TOTAL` в `certificate.html`
   и тексты «16 уроков» на страницах.
